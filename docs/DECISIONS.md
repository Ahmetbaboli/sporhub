- 2026-11-02 — **TR/EN: next-intl yerine küçük, projeye özel çözüm** (next-intl kaldırıldı). Gerekçe: mesajlarımızda fonksiyonlar var (`(n) => \`Son ${n} maç\``) ve tip güvenli tek kaynak istiyoruz; next-intl JSON + ICU ister ve URL'de dil öneki/middleware getirirdi. Tasarım: `tr.ts` anahtarların kaynağı, `en.ts` aynı şekilde (`Messages` tipi eksik/fazla anahtarı derlemede yakalar). Dil: `justsport-locale` çerezi → yoksa `Accept-Language` → yoksa TR; URL değişmez (paylaşılan linkler alıcının dilinde açılır). Sunucuda dil React `cache` ile **istek kapsamlı** bir depoda tutulur; her sayfa/metadata girişi `await initLocale()` çağırır, alt bileşenler senkron `t()` ile okur (eşzamanlı TR/EN isteklerle doğrulandı). İstemci bileşenleri `useT()` (layout'taki `I18nProvider`). Dil değiştirici JS'siz form + server action (çerez 1 yıl). Tarihler `Intl` ile seçili dilde (`tr-TR` / `en-GB`). Veri içeriği (takım/stadyum adları, API hata metinleri) çevrilmez.
